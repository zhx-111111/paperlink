# 📜 PaperLink

> 写一封信，等一个人。寄信 / 实时镜像两种模式的手写信笺应用。
> 完整方案见 [SPEC.md](./SPEC.md)。

技术栈：**Cloudflare Workers + KV + Durable Object**，纯静态前端（无构建步骤）。
手写引擎、溶解动画、毛玻璃 UI 嫁接自 [tom-riddles-diary](https://github.com/zhx-111111/tom-riddles-diary)（Riddle 网页版）。

## 🚀 部署（Cloudflare Workers）

> 本项目只走一条部署链路：**Cloudflare 官方的 Workers Builds（控制台 Git 集成）**——推送即自动构建部署。
> 原有的 GitHub Actions 工作流已移除，不要再同时配置第二条链路，避免互相覆盖。

**所有运行变量已在 `wrangler.jsonc` 中预设**，开箱即部署。唯一需要动手的是 KV 存储库——请先读下面这条重要机制，避免"绑定了却显示未绑定"。

> ⚠️ **KV 绑定必读**：每次部署都会用配置文件里的绑定**整体覆盖**线上绑定。
> 只在控制台手动绑定、却不写进 `wrangler.jsonc`，**下一次推送/重新部署就会被清掉**（这正是"绑定了却显示未绑定"的根因）。
> 正确做法：在控制台创建 KV 命名空间 → **把它的 ID 粘贴进 `wrangler.jsonc` 的 `kv_namespaces`** → 提交推送。此后绑定随配置永久生效。

### 粘贴 KV ID（推荐，最简单、绑定永久生效）

1. 先部署一次（此时无 KV，站点提示"未绑定"，属正常）；
2. 控制台 **Storage & Databases → KV → Create namespace**（建议名 `paperlink-kv`），复制命名空间 **ID**；
3. 打开 `wrangler.jsonc`，把 `kv_namespaces` 里注释行的 `<把你的KV命名空间ID粘贴到这里>` 换成该 ID 并取消注释（绑定名 `PAPERLINK_KV` 勿改）；
4. 提交并推送 → 绑定随配置生效且**永久保留**，无需在控制台再手动绑。

### 收尾

- **设置 Secrets**（Worker → Settings → Variables and Secrets）：
  - `PL_JWT_SECRET`：会话签名密钥（**必须设置**——v3.23 起不设置则拒绝注册/登录；已有历史 token 的校验不受影响）；
  - `ADMIN_PASSWORD`：管理页密码（默认 `paperlink2026`，**务必修改**）；
  - `SECRET_TURNSTILE`：可选，Cloudflare Turnstile 服务端密钥；不配置则注册免人机验证。
  - 已开启 `keep_vars: true`，控制台里设好的 Secrets / 变量不会被后续部署覆盖。
- （可选）Custom Domains 绑定自己的域名。

### 备选：wrangler CLI（本地手动部署）

### 排查"绑定了却显示未绑定"

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 控制台绑过，站点仍提示未绑定 | 绑定只在控制台、未写入配置，被后续部署覆盖 | 把 KV ID 写进 `wrangler.jsonc` 重新推送部署 |
| 绑定名写成了别的 | 绑定名必须是 `PAPERLINK_KV` | 改名或重建绑定 |
| 部署到了 Pages 而非 Workers | 本项目为 Workers（assets + DO） | 用 Workers 方式部署 |

## 🔧 参数（管理页可调，覆盖 vars）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `allow_register` | 开 | **是否开放注册**（关闭后 /join 拒收新用户） |
| `realtime_allowed` | 开 | 实时镜像总开关（实验功能，用户另需兑换码 RT） |
| `pending_page_limit` | 3 | 对方未读完前最多可发送的页数（1–10） |
| `keep_pages` | 10 | 每对话保留最近 N 页，超出 FIFO 遗忘（5–50） |
| `dormant_after_hour` | 24 | 房间无活跃超时（小时）→ 删信页；双倍超时彻底删房间 |
| `page_ttl_days` | 30 | 信页 KV TTL（天） |
| `max_pts_per_page` | 5000 | 单页笔迹点提示上限 |
| `cursor_sync_interval_ms` | 200 | 光标/逐点流同步节流 |
| `idle_timeout_ms` | 2500 | 新信横幅自动展开的空闲判定 |
| `pressure_min_width` | 0.6 | 压感最细笔迹（0.2–3） |
| `pressure_max_width` | 2.4 | 压感最粗笔迹（0.2–3） |
| `speed_factor` | 0.18 | 速度因子（0–0.5）：无压感设备快写变细的力度，0 = 关闭 |
| `pen_response` | pow | 笔锋响应曲线：pow（p^1.4）/ linear / quad |
| `default_theme` | tom | 默认信纸 |

## 🗝 管理后台（/admin）

- **运行诊断**：KV/Secrets 状态、会话/房间/信页/模板/兑换码计数、房间列表、休眠清理（先盘点出将休眠/将删除的房间清单，确认后才执行）；
- **兑换码**：按彩蛋/未公开信纸/未公开模板批量生成（含实验功能 RT），超大数量自动分批，CSV 导出（不含使用者身份）；
- **信纸模板**：上传 `.css`（≤50KB，仅允许作用于 `.page-paper`，拒绝 `@import`/外链 `url()`/脚本注入）+ 可选背景图（≤500KB），上传前有 3 秒效果预览；**默认不公开**，需手动公开或生成兑换码发放；
- **用户管理**：查看全部用户、重置密码、删除账号（删除时其对话名额与房间席位级联释放）；
- **音乐 · 网易云**：Meting-API 实例地址 + 网易云登录凭证（MUSIC_U cookie）填写，凭证只存服务端，代理请求时透传给上游，让灰色/会员歌曲取到可播直链。

## 💡 生产化设计（方案 → 上线之间解决的问题）

1. **KV 免费额度保护**：
   - 实时笔迹只走 WebSocket 广播，**不落 KV**；实时模式本身设为兑换码解锁的实验功能，控制使用面；
   - 房间活跃时间与在线计数的**权威数据在 Durable Object 存储**（v3.12），KV 仅按 60s/60min 节流兜底回写供管理页聚合；活跃时间离开房间时精确同步一次；
   - 在线计数 KV 回写仅 60s 心跳节流一次，连接/断开变化 5s 防抖合并后只落 DO 存储（v3.11/v3.12）；昵称/头像/主题偏好等用户信息全部本地化（`localStorage`），KV 只存跨设备必需数据；
   - 高频读走短 TTL 内存缓存：运行配置 60s、用户信息 60s、轮询房间对象 15s、DO 内实时开关 5min（v3.11，均为最终一致，实时性由 WS 事件保证）。
2. **注册开关**：`allow_register` 管理页参数，配合 Turnstile 双保险。
3. **限流与防刷**：注册（8 次/分/同 IP）、邀请码试错（20 次/分/同 IP）、提交（1.2s 冷却/用户）、WS 事件（60 事件/秒/连接丢弃）、提交载荷 ≤2.5MB。
4. **发送节流阀**：未读 3 页上限防止单方刷屏，同时压缩信页 KV 体积。
5. **休眠清理**：24h 无活跃删信页保元数据，48h 彻底删除，管理页可手动清扫。
6. **已知取舍**：内存限流为「单实例近似」——Workers 多实例各自计数，极端并发下实际放行量约为 实例数×上限（v3.23 已在代码内注明口径；关键接口另有 Turnstile 与密码哈希成本兜底）。WS 会话凭证原走 URL query 的问题已在 v3.23 解决（改由连接后的首条消息鉴权）。

## 📖 玩法

1. `/join` 注册（昵称 + 密码 + 头像），创建对话拿到 9 位邀请码，交给 TA；
2. TA 用邀请码加入，进入同一本日记；
3. **寄信模式**：写满一页点「发送」，墨迹被喝掉，信飞进对方书信集——TA 打开时笔迹由无到有逐笔浮现，可暂停/重播；
4. **实时镜像**（兑换码解锁）：⇄ 切换后落笔即见，横竖屏与信纸样式强制同步；
5. 对方未读完 3 页前不能再寄——等 TA 读；
6. 彩蛋用兑换码在「我的」页解锁。

## 🎨 自定义信纸模板

管理后台「信纸模板」支持**用户共创信纸**：

1. 在模板卡片点击 **下载信纸模板骨架**（或直接取 `public/templates/letter-template-skeleton.css`）；
2. 骨架已备好信纸与笔迹的逻辑骨架：底色/渐变、`var(--tpl-bg)` 背景图适配、纹理/横线/做旧伪元素、`var(--ink-color)` 呼应笔迹色——按注释填充自己的样式即可；
3. 管理页填模板名称 → 上传改好的 `.css`（≤50KB，须作用于 `.page-paper`）→ 可选背景图（≤500KB）与固定笔迹色 → 「上传并启用」；
4. 启用后所有用户的主题栏「更多」中即出现这张新信纸（等同一个已解锁彩蛋）。

服务端会校验：拒绝 `@import` / 外链 `url()` / 脚本注入，确保样式只作用于信纸容器。

**v1.2**（问题修复版）
- **修复对端擦除半径换算错误**：接收端漏除 VW 基准，半径放大 1000 倍，对方轻轻一擦本端整页被清空；
- **修复擦除事件回环**：对端镜像的擦除会再次上报给对方，两端互相回发形成事件风暴；
- **修复大厅 ⋯ 卡片菜单无法打开**：全局点击监听在菜单打开的同一帧把它关掉；
- **修复在线列表误判离线**：`online/{code}` 时间戳只在人数变化时写，人数稳定的房间 3 分钟后被管理页"陈旧记录"规则剔除；
- **降低 DO 写入开销**：活跃时间改为内存记账 + 30s 节流写 DO storage（原每条 WS 消息写一次）；
- **管理页防爆破**：同 IP 连续 5 次密码错误锁 5 分钟（补齐 SPEC §9 承诺）；
- **安全加固**：邀请码/兑换码改用 `crypto.getRandomValues`（原 Math.random 可预测）；管理令牌改恒定时间比较；模板墨色服务端白名单校验（防存储型 XSS）；WS 单条消息 256KB 上限；
- **修复注册页 Turnstile 一次性令牌问题**：提交失败后自动重置验证组件，第二次提交不再必然失败；
- **修复未读上限提示**：被拒收时前端读不到服务端返回的真实待读数（apiJson 错误对象未携带响应体）；
- 其他：卡片菜单位置越界钳制、登出跳转竞争等小修。
